# IronCandle — Setup Guide

IronCandle is dashboard-first. The browser stores only presentation state; the trading journal belongs in Supabase, while the market-history database lives in a compressed SQLite archive in Google Drive and is processed by GitHub Actions.

## 1. One-time historical bootstrap

The first run needs enough history to calculate the true monthly ATH, 52-week high and EMAs. The bootstrap uses Yahoo Finance/yfinance only once, because downloading many years of NSE daily archives file-by-file is unnecessarily large. After bootstrap, new daily rows come from the official NSE UDiFF bhavcopy and official NSE index-close file.

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python scripts/bootstrap_history.py --years 20
```

The bootstrap creates:

- `data/iron_candle_market.db`
- `data/iron_candle_market.db.gz`

Do not commit the DB. It is already in `.gitignore`.

## 2. Google Drive backup

Create or use a Google account with Drive enabled.

In Google Cloud Console:

1. Create a project named `IronCandle`.
2. Enable the Google Drive API.
3. Configure the OAuth consent screen.
4. Create an OAuth Client ID of type **Desktop app**.
5. Download the client JSON and save it locally as `client_secret.json` in the repository root.
6. Run:

```bash
python scripts/google_oauth_bootstrap.py --client-json client_secret.json
```

The script prints three secrets plus a Drive folder ID. It creates an `IronCandle_Backups` folder when needed.

Add these GitHub Actions Secrets:

- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `GOOGLE_REFRESH_TOKEN`
- `GOOGLE_DRIVE_FOLDER_ID`

The archive filename is `iron_candle_market.db.gz`.

## 3. GitHub repository

Push the repository to GitHub. GitHub Actions will run:

- Daily EOD market refresh: **18:30 IST, Monday–Friday**.
- Weekly fundamentals refresh: **10:00 IST, Saturday**.

The workflows restore the DB from Drive, process new data, write `public/data/scanner.json` and `scanner_history.json`, archive the DB back to Drive, and commit the public scanner snapshot.

## 4. Supabase cloud journal

Create a Supabase project. Run `supabase-schema.sql` in the SQL Editor.

Put the project URL and publishable/anon key into `config.js`:

```js
window.IRONCANDLE_CONFIG = {
  supabaseUrl: "https://YOUR_PROJECT.supabase.co",
  supabaseAnonKey: "YOUR_PUBLISHABLE_OR_ANON_KEY"
};
```

Never put the Supabase service-role key in the frontend.

RLS policies in the supplied schema make the journal user-scoped.

## 5. Hosting

The frontend is a static site and can be deployed to GitHub Pages, Vercel or Netlify. The scanner snapshot is a static JSON file generated by GitHub Actions.

## 6. No paid market-data API is required for the baseline build

### Daily market data

Official NSE UDiFF final bhavcopy + official NSE daily index-close file.

### Historical bootstrap

Yahoo Finance/yfinance, one time only.

### Fundamentals

Screener public company pages, refreshed weekly. IronCandle calculates annual PAT YoY, debt/equity, market cap, ROE, sales growth and OCF from the public statements it parses. Because this is website extraction, the adapter is intentionally isolated and can be replaced later if Screener changes its markup or blocks automated access.

### Optional later

- Broker API (Dhan/Zerodha) for positions/orders.
- OpenAI API for journal review and natural-language analytics.
- Chartink as an independent technical-validation source, not as the primary database.
